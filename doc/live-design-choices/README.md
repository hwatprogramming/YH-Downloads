# Live design choices

One file per feature that's built and in the app. Each records the options that
were on the table, which one was picked, why, and what the pick costs.

CLAUDE.md links here instead of carrying the reasoning itself. If you're about to
change how a built feature behaves, read its file first — some record something the
user tried and rejected.

| File | Covers |
|---|---|

## Writing a new one

When a feature ships, add its file here and a row to the table, then cut the
reasoning out of CLAUDE.md, leaving a link. Name the file for the feature —
`export.md`, not `decision-3.md`.

Keep the same shape: **what it is**, then a section per decision with the options,
the pick, and the cost.
